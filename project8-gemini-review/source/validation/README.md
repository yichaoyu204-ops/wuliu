# 现场验证手册

交付时表中仅有编号和实验分组。所有样本、工时、参与和付款都要等实际发生后填写。建议单指一条由操作员复核完整的业务运单，一票可含多条费用。一次对账批次可含多票，应预先固定范围。

## 1. 收齐材料并封存答案

1. 从同一供应商、同一费型的连续已结算业务中取二十个不同运单，每票配采购侧应付依据，并在 [样本登记](samples.csv) 标出格式、页/行、包含的费用行数、授权与采购依据状态。建议优先用已覆盖的表格格式。两个文件属于同一票时合计为一个样本。同一发票跨多个运单时，按整张发票分组，同组不跨校准和盲测。只取已出过错的历史票会高估收益。
2. S01–S05 用于弄清模板和口径。S06–S20 为十五票独立留出。材料保管人保留原件；向操作员给脱敏副本，保留可复查的相对页码/工作表/行。弃用的候选及理由另记，下一个合格样本方可补位，不把难样本静默丢掉。典型异常没出现在连续样本里时，可另设挑战样例，只报功能测试。
3. 采购或财务复核者在运行前独立填写 [答案模板](truth-template.csv)，正常行和存在异常的行一并标注。账单缺失的预期行也独立列出。无法确认的注明“未知”，不得猜测。保存带日期的只读副本，工具操作者在揭盲前看不到答案。这里放的是空表结构；真实答案、原件及身份对应表各自保存在获准的非共享目录，不跟随项目分发。
4. 冻结版本和输入范围。保留首次输出，再揭盲，与可判定的原件和采购依据核对。在 [逐项判定表](decisions.csv) 分别列上所有系统告警与所有真实异常，避免仅检查系统自己标红的行。收到异议由第二位业务人员复核。改版后另记为回归测试；同一留出集已曝光，新的准确性主张需另收未经调试的新票。

## 2. 同口径计时与判定

在 [盲测及计时](trials.csv) 一次登记一个“方法 × 业务批次 × 操作员”。事先约定同一组业务、同一开始状态（已获授权并拿到双方文件）、同一完成状态（每项有可核查的处理意见和可交付的 Excel）。至少比较客户现行做法和试点工具。能实际使用其他产品时，在相同输入下增加第三种方法并记入实施成本。

建议两位操作员交叉测试两组相近资料。第一组由甲按原方法、乙按试点流程，第二组交换方法。单个操作员独自测试时按相近票量分组、交替使用两种方法，记录票量和难度，只做探索性比较。不得让同一人记住同一批答案后再做另一轮。两个人使用相同输入时独立完成、互不看答案。样本批次的费用数、异常密度或操作员经验差异应在备注说明。

- 每种方法的人工分钟合计 = 准备/转录 + 操作 + 复核/返工 + 导出。全程耗时另录，含等待。样本收集授权的一次性工时与日常操作的工时分列。把自动运行的等待时间算成节省的人时会高估成效。
- 一次对账净省人时 = 相同范围的原流程人工分钟减试点人工分钟。单次达到 120 分钟才满足原计划的该项条件；逐月外推另列假设，不能拿累计多次的时间冒充单次。
- 以“运单＋费用行＋异常类型”为判定单元。一个真实异常最多命中一次。命中为报告异常且双方原件支持；误报为报错但复核正常；漏报为已知异常未命中。将转人工、无法判定真值的数量单列。对已知真异常，工具只给“转人工”时仍算自动漏报，可另统计最终人工发现。正常票上触发的人工复核同样计入工时。
- 同时报告两种分母。异常命中率＝命中÷（命中＋漏报），告警准确率＝命中÷（命中＋误报）。分母为零就写“无法估计”。另报所有盲测件中的成功处理票数、需要转录票数、每笔告警来源可追溯率及人民币/外币各自确认可追索的金额。确认差错、提出申诉、供应商承认和实际追回分别记录。
- 五票校准和十五票留出分别报数。某一票有多行费用不能产生多张独立样本。多个币种分币种汇总。若只有一位操作员、单一模板或部分授权，在结论中标注相应限制。

**业务继续门槛。** 至少一次有原账、采购依据和负责人确认的真实差错，或同口径的一次对账实测净省两小时，可启动有价试点询价。建议将“每笔已导出的可比差额均能回查双方依据、留出样本中未发现静默放行的重大金额差错”作为继续有限试用的工程门槛。重大金额的阈值由负责人在揭盲前按币种写定。若样本中没有真实重大差错，只能记为该能力尚未覆盖。一个真实事件只能证明这个场景值得再试，实际付款、独立客户重复使用和人工服务成本还要继续记录。若现成工具更省钱且表现相当，优先采用现成工具。

## 3. 邀请、后续与付费

[种子用户登记](testers.csv) 预留五个代号，其中三个位置优先给三家不同企业、能决定预算的老板或财务负责人，另外两个可约实际核账的操作员。先取得其同意，由对方选择是否可以导入脱敏副本、是否仅现场运行、允许谁看输出、哪天删除。项目中只保留代号。未取得资料用途授权时只展示公开演示，不登记为真实样本。

**发给同行的邀请草稿**

> 最近我们在试一个货代对账方法，想知道它能不能比你们现在的 Excel 或系统更快发现附加费差异。能否约 20 分钟先看一笔已经结清的业务？你可以亲自在自己的电脑上操作，先遮住客户、供应商和单号，仅保留费用、单位、金额及对应依据。有些单据还需要人工复核。你认可用途和删除时间后我们再试，只用于本次对账评估。也欢迎告诉我现在怎么核、哪一步最费时。

**有真结果后的回访草稿**

> 这次核了［票数/费用行数］，由你们确认的差错是［结果或无］，两种流程的人工分别是［分钟］和［分钟］，还有［未决事项］。这个结果值得你下次继续用吗？下一批大概几票、由谁决定费用？如果合适，我可以按 199 元做一期 30 天的试点，限定一个供应商、最多 20 票，交付逐票差异表和人工复核说明。你愿意按这个范围排下一批吗？若现有方法更合适，也想知道具体原因。

199 元是本次询价假设，报价时先确认实际范围和能承接的工时。未获同意不对外发消息。[反馈与问题](events.csv) 按事件登记。口头兴趣、接受明确价格、安排下批日期、实际收款、第二次实际使用分别记录日期与可核对的依据。只有到账才计已付费；一期试点贡献＝实收款－交付人工时数×实际小时成本－工具、支付等直接费用。客户端可另算净效益＝节省人工价值＋实际追回金额－试点费用及额外实施成本。记录各项口径，避免把发现的差额和追回金额重复计入。

## 4. C3 语音排版卡片的推广草稿与三组画面

面向习惯口述复盘、已经用语音转文字或排版工具的中文用户。让体验者用同一段自带的话分别走现有流程和原型。若设备不支持语音识别，写明使用粘贴文字的路径，不能把它算作语音转录成功。对每位用户只记完成时间、实质更正轮次、导出是否成功、是否真实自用/分享及七天内再次制作。先定下希望表达的原意，导出前让本人检查是否被改错。

**社群贴草稿**

> 我最近做了一个小工具，想看看手机里那些说完就放着的语音，能不能很快变成一张自己愿意留着的复盘卡。想找几位平时会口述或做小红书图文的人，用自己方便分享的一小段话走一遍。你最想保留哪句话？哪句被改得不像你？欢迎把现在的做法也一起比一比。内容可以用现场编的一段，作品是否公开由你决定。

| 三秒画面 | 拍法 | 观察什么 |
| --- | --- | --- |
| 同一句“今天报价差点把磅当公斤”，从口述到一行大标题 | 首帧保留口述字幕，第三秒切到真实导出卡；整段实际耗时另标明 | 用户是否知道下一步该说什么，导出的语义是否准确 |
| 一段有停顿、口头禅的真实复盘，卡片保留用户自己选的那句 | 分屏标出原句及卡片对应位置，展示更正一次再导出 | 用户修改几次、是否保留原意 |
| 同一段话发朋友圈前的最后一步 | 左边记录用户现有排版流程，右边记录本工具导出，展示真实计时与结果 | 用户是否保存或发出作品，七天后有无再来 |

商业证据以同一明确价格/权益的实际接受及购买为准。如需测试，可对体验完的用户展示“6 元解锁一组额外模板”的价格卡并征询购买意向。价格卡必须说明是否已开通购买。若尚无支付功能，仅登记愿意按价购买和原因。播放、点赞、转发、保存、真用、付费分别报告；未做公开投放时不填写曝光数据。两项试点的数据分别标记 B2B 和 C3，不共用分母。

## 5. 如何登记缺陷

在 events.csv 中给每个事件写一行，保留测试版本、角色代号和样本代号。故障从“新发现”开始，写清复现条件、预期与观察差异。修复时关联改动版本，让与开发不同的复核者用原案例和一份相邻案例重测，再写复核结论和日期。有关人名、付款凭证和原账单内容仅在批准的范围留存，表中使用证据代号。没有复测证据的缺陷保持“待复测”。
