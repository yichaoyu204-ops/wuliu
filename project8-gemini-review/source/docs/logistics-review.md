# 物流业务审查与对账试点规格

## 这次要决定什么

现有义乌、宁波集货小程序服务客户收货和报价。保留这条业务入口。另用一次内部试点判断，操作员逐票核对供应商账单时，能否少花时间或发现值得追索的金额。客户报价单属于销售侧；试点要求的是采购侧已确认应付依据。仅凭客户收费表算出的差异不能拿去向供应商追款。

本轮先选一个能取得采购依据的供应商和费用类型，面向已经在用 Excel 或货代系统的操作员与财务。付费决策人假设为老板或财务负责人，待访谈核实。暂缺可公开核验的订单量、对账时长、错账率和付费记录；这些是要测的量。

| 原计划的六个问题 | 对本项目的判断及行动 | 反证或暂停条件 |
| --- | --- | --- |
| 换系统的成本有多高 | 保留后台辅助对账，沿用客户原表导入，输出可在 Excel 复核的差异单。向一线问清上一次对账如何结束，另记找文件、转录、复核和导出的分钟数。 | 整理输入比现有对账更费时，且没有发现新增的可追索差错。 |
| 算错由谁负责 | 每笔差异并列账单原值、采购依据及两处位置。币种、计费单位、重复候选、缺少采购依据进入人工复核。操作员查原件，采购或财务负责人确认后才可提出异议。 | 存在错误安心放行、猜测费率、把多条候选强行合并，或任一方无法核查来源。 |
| 用的人和付钱的人是谁 | 分开找操作员计时、找有预算的负责人确认月单量、采购流程与可接受价格。同一家公司多人使用只算一个采购决定。 | 有称赞或转介绍，负责人仍不愿提供下一批账单或接受具体报价。 |
| 谁会愿意交出底价 | 先取得允许的使用范围，再用一致别名代替客户、供应商、运单号。删去电话、地址、账号；采购金额、单位和对应关系仅在获准的本机保留。可由对方现场操作。 | 拿不到使用权限或成对的采购依据时，该票记为缺件，不做正确率样本。 |
| 客户为何不用 Excel、聊天助手或现有对账产品 | 先和客户当前最快的做法对照；能拿到有权限的现成产品，也以同一份采购依据、币种和人工复核标准比较。只检验本地模板适配、证据能复查、减少人工和持续处理相似单据的价值。 | 成熟工具或 Excel 可以同等可靠地完成工作，且总成本更低；应直接复用。竞品存在不等于其覆盖了这个供应商的原始格式。 |
| 七天能验证什么 | 前五票校准，另外十五票封存答案后测试；至少三位独立同行老板或财务决策人参与，种子测试共三至五人。记录一次确认差错或一次对账净省两小时后，再出价测试。 | 样本不足、无人参与或未收到真实回复时，报告实际分母和缺口。反馈截止时可结束试点，不能据此宣布市场验证通过。 |

## B2B 试点规格

**一个业务输入包**包括供应商账单与逐票、逐费用已确认的采购应付依据。最低字段为供应商别名、运单别名、费用名、币种、计费单位、行金额和可回查的来源。底表如果只有每公斤单价、区间阶梯、体积重或临时豁免，先由操作员按当时约定核出应付行金额并记录依据。试点实际验收范围是从已有的应付行金额查出账单差异。

**一个核对过程**先提取候选行，再按供应商、运单、费用、币种和计费单位进行确定性比对。分别保存原值、规范化值与来源。提取状态区分自动读入和需人工复核；不得把未校准的分数解释成准确概率。CSV/XLSX 以可识别表头为起点；文字 PDF 限于可辨列版式。扫描件或复杂 PDF 允许人工转录并计入工时。异常目标包括金额不符、缺依据、账单缺项、单位或币种不一致、重复/多候选、关键字段缺失。能力逐项以实际版本运行结果为准。

**一个导出结果**为 Excel 复核清单。每项应显示运单、费用、双方原金额、币种/单位、可比时的差额、异常原因、双方来源及人工复核记录。导出工作簿包括“对账明细”“逐字段证据”和“文件与未决事项”。正式应付或向供应商申诉仍由负责人确认。

**五项本期边界**

1. 自动裁决、提交申诉及向外发送供应商邮件留给业务负责人。
2. 汇率、跨单位折算、体积重、税费及阶梯价换算留在采购侧确认环节。
3. 全版式 OCR 和无表头扫描件的自动结构化留给后续需求评估。
4. 现有 ERP 和收货小程序继续承担原有工作，试点通过文件交换。
5. 多租户后台、账户体系和在线收款延期。试点报价与付款证据另册记录。

**字段契约。** 两种输入分别标为 `invoice` 和 `baseline`。操作员负责识别采购性质。如果带有六个同名字段的客户销售表被误选，程序无法单凭表头辨别其商业性质。每条记录包含六个业务字段 `supplier`、`shipment`、`charge`、`currency`、`unit`、`amount`。每一项均以 `{value, source_ref, evidence, confidence}` 保存；确认或修改字段时可额外保留 `original`。字段来源与文档名及 SHA-256 结合使用：表格定位至工作表和单元格，PDF 提取定位至页、行和列名。缺失字段仍保留来源行。当前 `confidence` 为流程状态，例如“表头直接读取”“待人工”“缺失”“人工转录已核”，不把这些状态换算成概率。候选提取如使用可选本地模型，其结果仍需操作员逐行核实。

### 十个软件工作包与独立验收命令

在交付项目根目录运行，推荐 Node.js 24。命令调用核对台实际使用的 `b2b/core.mjs`、`b2b/formats.mjs` 及随附 ZIP 实现，使用工程合成记录。下列操作均不会读取真实业务文件。整套运行命令为 `node validation/check-spec.mjs all`。

| 软件工作包 | 可重复的验收动作 | 独立运行命令 |
| --- | --- | --- |
| 输入包与文件识别 | 分别导入账单和采购 CSV，校验文件指纹；表头仅有单价时留下待核原因 | `node validation/check-spec.mjs intake` |
| 表头、引号与物理行定位 | 中文表头、UTF-8 BOM、含逗号和换行的字段可以读取，错误引号及重复表头可识别 | `node validation/check-spec.mjs csv` |
| 六字段证据契约 | 逐字段核对原文、单元格和置信状态，缺金额进入待核 | `node validation/check-spec.mjs fields` |
| 候选记录与人工复核 | 用模拟的 PDF 列、行及含公式的表格行喂入正式记录提取函数，确认候选保留来源且不产生差额 | `node validation/check-spec.mjs candidates` |
| 唯一匹配与重复 | 同票不同费用正确配对；任一侧出现同键多行时产生待拆分记录 | `node validation/check-spec.mjs match` |
| 金额比较 | 高低差各一分、千位分隔、畸形小数按规定处理 | `node validation/check-spec.mjs amounts` |
| 币种和计费口径 | kg/公斤同义匹配；磅/公斤、美元/人民币均须人工确认 | `node validation/check-spec.mjs units` |
| 双向查漏 | 只有账单、只有采购依据时分别显示正确的缺件方向 | `node validation/check-spec.mjs missing` |
| 复核意见与导出映射 | 人工状态、备注和两端来源出现在差异明细；证据表含双方的六字段 | `node validation/check-spec.mjs review` |
| 合成文件端到端导出 | 读取两份示例 CSV，经过核对后生成真正 XLSX 并解包检查三张表、地址及文件指纹 | `node validation/check-spec.mjs workbook` |

以上十项由 Node 直接运行。另运行 `node b2b/tests/e2e.cjs` 可用浏览器复核双工作表 XLSX、指定列布局的文字 PDF、无文字空白 PDF 转人工、从页面保存意见和下载 XLSX。该命令使用 Playwright、pdf-lib、jszip 和可用的 Chromium/Chrome；空白 PDF 只验证无文本时的处理路径，真实扫描件另测。可选本地模型的模拟接口测试运行 `node --test b2b/ollama.test.mjs`，真机模型是否可用及其提取质量须另验。客户页的两个上传入口分别标为“选择账单文件”“选择采购基准”，操作员在结果页复核后用“导出 Excel”保留当前结果。浏览器刷新前需导出。

### 人工业务复核清单

这些是可以交给另一位复核者重复执行的验收动作。各项可用各自的脱敏测试样本，随后再做端到端测试。工程样例只验证行为，真实样本用于商业判断。

| 项目 | 复核者的独立操作 | 合格证据 |
| --- | --- | --- |
| 1. 输入契约 | 对齐一对真实文件的采购与销售口径，另给一份只有客户报价的底表 | 前者可说明金额依据，后者被标记资料不足，两者不混用 |
| 2. 表格读取 | 分别导入含中英文表头的 CSV 和多页 XLSX，检查源行及分表范围 | 成功行能回到原表，跳过的页或行可见 |
| 3. PDF 处理 | 输入列清晰的文字表、扫描件各一份，操作员按页核对 | 前者来源可复查，后者进入待转录/复核；两种情况分别计时 |
| 4. 唯一匹配 | 以同一运单中两项不同费用、两笔同名候选组成测试 | 两项费用不串行，多个候选交人工 |
| 5. 数值、单位和币种 | 测试相同币种/单位的有差额及无差额行，再测试币种或单位不同 | 首组差额等于人工重算；第二组禁止直接相减 |
| 6. 双向查漏 | 分别保留只有账单一侧、只有采购依据一侧的费用 | 说明哪一侧缺失，账单缺项与已确认漏收分列 |
| 7. 复核与导出 | 分别检查金额差、不能比较的行、无差异行，填写意见并在 Excel 重开 | 金额/来源/意见可读，人工认定和系统初判可区分 |
| 8. 五票校准 | 按校准集观察缺字段、无表头和人工转录所需时间，记录版本 | 五票逐票有结果和处理工时，冻结下一轮待测版本或写明阻塞 |
| 9. 十五票留出测试 | 独立保管人预先写下答案，测试人提交结果，再按本包方法揭盲 | 同时报命中、误报、漏报、弃判与来源可追溯数；依计划单元记录净省分钟 |
| 10. 外部与收费验证 | 给三至五名同行提供一次授权、脱敏试用，向至少三位独立决策人核实预算和下一批需求 | 逐人记录实际动作；免费测试、接受具体价格、实际到账和再次使用分别登记 |

操作表和草稿见 [现场手册](../validation/README.md)。
