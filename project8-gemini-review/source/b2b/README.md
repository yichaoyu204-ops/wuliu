# 运费核对台

将供应商账单与已确认的逐票采购基准比对，查看行金额差异与字段出处，导出供操作员或财务复核的 Excel。默认在浏览器中处理，刷新会清空本次明细和备注。示例文件全部为合成数据。

## 打开

使用近期桌面版 Chrome 或 Edge。进入本目录，运行以下命令，然后打开[中文工作台](http://127.0.0.1:8765/)或 [English workspace](http://127.0.0.1:8765/en.html)。英文页支持文件导入、原文核对、补录、复核备注和英文 Excel 导出。原始业务文本按原样保留。按 Ctrl+C 停止服务。运行应用仅需 Node.js，无需安装 npm 包。

```text
node start.cjs
```

在已有的静态空间部署时，将本目录中的两个 HTML、CSS、五个应用模块、vendor 和 samples 放在同一子目录，使用 HTTPS。MJS 须以 JavaScript MIME 返回。也可使用 Python 的 `python -m http.server 8765 --bind 127.0.0.1`。直接双击 HTML 会受到浏览器本地模块限制。

## 完成一次核对

1. 导入供应商账单及独立的采购依据。每侧都可同时选择多个文件。使用“载入合成示例”可先查看七种常见结果。示例包含 7 行账单、6 行采购基准，得到 8 条核对结果。
2. 点击行尾“查看 / 复核”检查双方六个字段的值、来源和当前依据。点击“校正或确认字段”并填写原文依据后重新计算。误提取的页脚或重复模型候选可在字段界面填写原因并排除。文件或字段改变后只清空受影响行的旧复核结论。
3. “原件与明细”可查看整份文件的导入提示、源文件与 PDF 页内文字。扫描图片或未知格式通过“补录明细”录入，并给出页、行及原文笔记。文件问题核清后填写整份文件核对说明。
4. 选择处理状态、录入备注并保存。点击“导出 Excel”得到对账明细、逐字段证据、文件与未决事项三张表。缺失基准、尚待确认或单位不同的记录保留空差额。不同币种的金额不汇总。导出的文件名和字段均作为文本写入，金额差额独立作为数字类型。

## 输入

| 字段 | English header | 要求 |
|---|---|---|
| 供应商 | Supplier | 双方一致，别名差异由人确认 |
| 运单号 | Shipment | 唯一业务编号，保留前导零时使用文本单元格 |
| 费用名 | Charge | 同票多行同名同单位同币种需另行拆分或澄清 |
| 币种 | Currency | CNY、USD、EUR、GBP、HKD、AUD、CAD、SGD、NZD、CHF |
| 计费单位 | Unit | 识别 kg/公斤、lb/磅等同义单位，不跨单位换算 |
| 行金额 | Amount | 已确认的本行含义一致的总额，最多两位小数 |

采购价目表里的单价需要先结合真实运量、有效期、合同、费用条件和凭证算成该运单的预计应付行金额。对客售价无法直接确定采购成本。小计与总计应单独排除，以免重复计数。现阶段根据供方、运单、费用名、币种和计费单位匹配，分别复核金额、缺项、重复与候选冲突。

- **CSV** 支持 UTF-8、双引号转义、逗号/制表符/分号分隔。首个非空行须是可识别表头。位置如 CSV!F3。
- **XLSX** 逐张普通工作表读取首个非空表头，保留工作表名和坐标。直接读取单元格的存储值。合并表头、用单元格样式补前导零或多层表头应先整理。含公式的行需人工确认其缓存数值，不执行公式。
- **PDF** 带文字层、同一行六列表头、列位置对齐且每条费用占一行时生成候选，每条都须人工确认。仅图片、版式错位、跨页断行或未识别表头会进入人工核对。页内行号指自上而下的文字行；在原件定位时并看字段证据。没有内置 OCR。
- 单文件上限 24 MiB，PDF 最多 100 页，单张 CSV 或工作表最多 2 万行，XLSX 展开上限 90 MiB。
- 支持差额初筛；没有税务判断、自动申诉提交、退款追回或合同义务裁定功能。

可选本机模型只在人工选中 PDF 页、明确模型名并点击按钮后接收这一页文字。模型输出均作为候选。详见 [本机模型设置](./OLLAMA.md)。

## 验证

```text
node --test tests/core.test.mjs ollama.test.mjs
node tests/e2e.cjs
```

浏览器测试需要 Playwright、pdf-lib、jszip 与 Chromium/Chrome，可通过现有 Node 模块查找路径或 `CODEX_PRIMARY_RUNTIME_NODE_MODULES` 配置。设置 `CHROME_PATH` 可指定浏览器。测试在虚构 HTTPS 地址拦截请求并返回分发的静态文件，无须公网、真实合同或客户资料。覆盖两个示例文件、异议复核和导出、文字 PDF、无文字层 PDF、两张工作表、重复文件、异常表头及窄屏布局。测试直接检查浏览器实际生成的工作簿字节，`node tests/e2e.cjs --save-export` 可重新生成 [示例对账底稿](./samples/example-review.xlsx)。

PDF.js 5.6.205 和 JSZip 3.10.1 为随包分发的浏览器依赖，许可证在 vendor 内。CMap 附有独立许可证。
