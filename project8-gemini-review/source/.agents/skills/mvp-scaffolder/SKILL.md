# 最小可运行原型

1. 从真实用户任务写一句验收语句，包含输入、输出、最常见的失败情形以及用户如何判断结果有用。检查已有工具、目录、数据结构和入口，列出可以直接复用的部分。
2. 从最窄支持范围入手。若试算表已能计算报价、用户只想试清单，先做输入到清单的一条路径。按项目原有约定选择格式、运行环境和命令。
3. 隐去样例中的身份信息，给构造案例加醒目的“示例”。实现能够落地的正常输入、缺字段和边界三条路径。保留原始输入、出处、结果及复核状态。
4. 按用户将采用的入口实际走一遍，打开导出物并检查关键字段。写下可复跑命令、预期输出与当前通过的用例。外部集成缺凭据时说明哪些个案尚未覆盖。
5. 对照现成流程，同任务记录完成时间、人为改动次数和是否采用。技术跑通与业务效果分别报告。让下一次开发针对第一次试用暴露的具体缺口。

**示例。** 对账原型只接收一份已转成行项目的明细和匹配的采购价表，输出“正常、待补证、需核差异”三种状态。首个验收可用控制台或表格，不依赖部署、账号和支付。

需要从空目录打样时，在项目根目录运行 `python .agents/skills/mvp-scaffolder/scripts/create.py demo-local --title 单号复核`。双击新目录的 `index.html`，或用浏览器打开它。运行 `node --test demo-local/app.test.cjs` 可核对初始任务的正常、空值和长度边界，再把输入和测试改为目标业务。
