# 界面打磨

1. 在现有界面实际走一遍一个主任务。记录起始视窗、用户首次要点哪里、完成与失败反馈出现的位置。优先列出阻止完成、造成误读或需要反复定位的三个问题。
2. 先修操作顺序和文案。让输入的单位紧跟数值，主动作靠近当前输入，待确认状态同时用文字和可见样式。对外导出前明确样例、估算、确认结果的区别。
3. 沿用核心字体和品牌色。调整窄屏内容顺序、长名称换行、焦点顺序、文字对比与点击区域。保留用户当前输入，让错误信息告诉用户改哪一项。
4. 在窄屏与常用桌面宽度实际跑正常、空白和错误路径。检查键盘可达性与结果保存或导出。有设备时实机验证；只有浏览器模拟时写明视窗和模拟范围。
5. 交付每轮修改前后对应的具体任务结果，如导出按钮从横向滚动区移到主表下方，及按窄屏尺寸重新操作后的结果。测试者完成时间或使用反馈需真实取得。

**示例。** 原型含“已知费用小计”和“整票待确认”，缩小屏幕后仍须同时显示状态和货币。仅调整配色不能解决总额误读。可使用项目 `knowledge/product_design/comparison.md` 的同任务对照方法。
