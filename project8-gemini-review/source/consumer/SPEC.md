# 寄语 Dispatch Notes · 原型规格与验证

## 这一版试什么

货代、外贸小卖家和仓库跟单人员常要把临时进度发给客户。本轮假设是，在客户群里发送一张能独立看懂的图片，可能比编辑微信文字或套用设计模板更省时间。用户也可选择随手记样式。是否需要以图片发送，本身就是第一个待验证的问题。

原计划第 3 个方向的直接替代品 Draft AI 已把录音转为可导出的社交图文。开发者在商店页列有 30 秒语音、自动排版和 PNG/PDF 导出。它对中文货代业务的质量和速度尚未比测。[开发者产品说明](https://apps.apple.com/us/app/id6749152418)

## 功能和视觉

一页容纳原文编辑与实时成图。手机依次排列编辑区、预览区，有页内预览跳转。两个主操作是开始或停止口述、保存 PNG；勾选框、下拉框和文本框用于调整内容。界面可切换中英文，用户录入的正文保留原文。支持浏览器原生语音识别的环境仅在用户点击后请求使用麦克风。识别失败或离线时可粘贴、输入，或使用设备键盘听写。是否向浏览器供应商发送音频取决于浏览器；本应用没有账号、上传接口、AI API 或埋点。

整理只移除有明确标点分隔的语气词，如「嗯，呃，」；开关可关闭。产品不推断或补写出货日期、数量和承诺，也没有实现通用 AI 金句提炼。保留原始输入，用户可校正识别内容。超过 600 字时提示缩短，禁止导出，避免截断。长文逐行测量，图片按需要增高。预览直接展示最终 Canvas。下载未弹出时可打开生成的图片保存。

## 三条 3 秒传播画面草案

以下素材与业务单号均为虚构。只测试第一眼能否看懂，未向任何平台发布。

1. **同一句话两种发法。** 左侧展示两行夹有「嗯，呃，」的原稿，右侧展示同一句的出货卡。第三秒定格相同的「DEMO-27 / 3 箱」。文案「你的客户收到哪份更好读？」
2. **少发错一句承诺。** 展示「预计周五，待仓库确认」；手指打开预览并放大「待确认」。文案「把不确定的事，也说清楚。」画面只展示工具保留原文。
3. **断网还能发起制作。** 在飞行模式画面，把虚构的「DEMO-08 已入仓，2 箱」粘入文本框，切到成图并保存。文案「仓库没网，先把通知做好。」可以离线生成图片，发给客户仍需通信网络。

## 定价与成本实验

首轮试用免费，同时访谈对方最近是否发过这种图片、目前花几分钟、微信群文字是否已经足够。可用同一份真实脱敏文本比较微信纯文字、现有工具和此原型的完成时间、返工数，以及接收者能否准确复述件数和待确认事项。顺序轮换，计时从拿到输入到能发送，包括校对和保存。建议收集至少 5 名真实用户的实际任务；若没有 2 人愿在第二次业务中主动使用，先暂停美化。该门槛是本次实验判断线。

对确有复用的人再测试人民币 12 元/20 张品牌模板包；原型没有收款。定价、平台费率、使用量、成交量均未验证。假设平台或支付成本按实收的 5% 计，每包其他可变成本 0.20 元，全额购买并用完 20 次；要使毛利率严格大于 80%，每包变量成本必须小于 2.40 元，因此每张增量 AI 成本必须小于 (2.40 − 0.60 − 0.20)/20 = 0.08 元。本原型自有 AI API 调用为零；正式渠道的费率、税费、退款、获客、运营和人工须单列核实，浏览器识别能力不可视为自有服务能力。

若相同任务由微信文字或现有软件同样快且更受接收方欢迎，退出该方向。可继续的依据是重复使用或真实购买，加上可复核的时间、错误或沟通轮次改善；样例图与录屏只证明技术流程。
